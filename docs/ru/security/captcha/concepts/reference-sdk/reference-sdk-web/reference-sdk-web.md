## {heading(Смонтировать капчу)[id=reference-sdk-web-render]}

Метод `captchaWidget.render()` монтирует капчу на страницу и запускает сервис капчи. Метод вызывается один раз на загрузку страницы.

Пример вызова метода:

```typescript
await captchaWidget.render({
   link: captchaLink,
   lang: 'ru',
   invisible: true,
});
```

## {heading(Запустить проверку пользователя)[id=reference-sdk-web-execute]}

Метод `captchaWidget.execute()`:

- запускает проверку пользователя;
- отображает всплывающее окно с капчей, если это задано {linkto(#reference-sdk-web-render)[text=методом]} `captchaWidget.render()`;
- возвращает токен успешного прохождения капчи для передачи бэкенду.

Метод вызывается один раз на смонтированную CAPTCHA-сессию. Обычно это целевое действие пользователя, например отправка формы, но проверку можно запускать и по ответу вашего бэкенда, который потребовал капчу.

CAPTCHA-сессия расходуется первой же проверкой: после успешной проверки повторный вызов метода отклоняется с ошибкой `already_checked`. Чтобы запустить следующую проверку на той же загрузке страницы, снимите капчу {linkto(#reference-sdk-web-destroy)[text=методом]} `captchaWidget.destroy()` и смонтируйте ее заново {linkto(#reference-sdk-web-render)[text=методом]} `captchaWidget.render()` с новой ссылкой из ответа {linkto(../../../../../tools-for-using-services/api/api-spec/captcha-api#api-spec-captcha)[text=метода]} `GET /captchaNotRobot.createSession`.

Пример вызова метода:

```typescript
const successToken = await captchaWidget.execute();
```

Параметры метода `captchaWidget.execute()`:

[cols="2,2,2,4", options="header", width=100%]
|===
|Параметр
|Обязательный
|Тип
|Описание

|`timeout`
|![](../../../../../assets/no.svg "inline")
|`number`
|Таймаут ожидания ответа от сервиса капчи в миллисекундах. Значение по умолчанию — `10000`.

Отсчет начинается с момента вызова метода. Если капча еще загружается, ожидание загрузки входит в таймаут.

По истечении таймаута promise-объект отклоняется с ошибкой `timeout`, но капча остается на странице: следующий вызов метода `captchaWidget.execute()` уйдет в сервис капчи, как только капча загрузится.

Если капча развернулась в видимое задание, таймаут снимается, пользователь решает задание без ограничения по времени
|===

Метод возвращает promise-объект с результатом проверки:

```console
promise resolve <ТОКЕН_ПРОХОЖДЕНИЯ_КАПЧИ>
promise reject <ОШИБКА>
```

Здесь:

- `<ТОКЕН_ПРОХОЖДЕНИЯ_КАПЧИ>` — токен успешного прохождения капчи, если пользователь прошел капчу;
- `<ОШИБКА>` — код ошибки.

Коды ошибок:

|Код

|`not_initialized` 
|Метод `captchaWidget.render()` не вызывали или он завершился с ошибкой 

|`not_passed` 
|Пользователь не взаимодействовал с капчей

|`timeout` 
|Ответ на проверку не пришел за отведенное время 

|`token_expired` 
|Время действия токена истекло

|`failed` 
|Проверка провалена или ошибка виджета капчи

|`already_checked`

|`close`

## {heading(Подписаться на события)[id=reference-sdk-web-events-on]}

Для подписки на события используется метод `captchaWidget.on()`. Имена событий доступны как свойства объекта `CaptchaPublicEvents`.

Пример вызова метода:

```typescript
import { CaptchaPublicEvents } from '@vkid/captcha';

captchaWidget.on(CaptchaPublicEvents.SUCCESS, () => setCanSubmit(true));
```

[cols="3,2,5", options="header", width=100%]
|===
|Событие 
|Данные 
|Когда отправляется 

|`captcha: success` 
|`{ token }` 
|Проверка пройдена. Во встроенном чекбоксе — в момент нажатия флажка

|`captcha: challenge visible` 
|![](../../../../../assets/no.svg "inline")
|Невидимая проверка развернулась в видимое задание 

|`captcha: challenge hidden` 
|![](../../../../../assets/no.svg "inline")
|Видимое задание свернуто 

|`captcha: token expired` 
|![](../../../../../assets/no.svg "inline") 
|Время действия токена истекло, отправлять его бэкенду уже бессмысленно 

|`captcha: load slow` 
|`{ slowLoadAfter }` 
|Загрузка приложения капчи идет дольше порога `slowLoadAfter`, указанного в методе `captchaWidget.render()`. Это не ошибка, капча продолжает грузиться
|===

{note:warn}
Подписывайтесь на события до вызова метода `captchaWidget.render()`, иначе ранние события потеряются.
{/note}

При использовании {linkto(#reference-sdk-web-show)[text=устаревшего метода]} `captchaWidget.show()` события не отправляются. Результат приходит только promise-объектом метода.

## {heading(Отписаться от событий)[id=reference-sdk-web-events-off]}

Для отмены подписки на события используется метод `captchaWidget.off()`.

Пример вызова метода:

```typescript
import { CaptchaPublicEvents } from '@vkid/captcha';

captchaWidget.off(CaptchaPublicEvents.SUCCESS, onSuccess);
```

{note:warn}
Передавайте ту же функцию-обработчик, что и в методе `captchaWidget.on()`. Без нее подписка не отменяется.
{/note}

## {heading(Скрыть капчу)[id=reference-sdk-web-hide-popup]}

Метод `captchaWidget.hidePopup()` скрывает виджет капчи, не прерывая проверку. Сервис продолжает работать, повторный показ виджета мгновенный. Метод ничего не возвращает в ответе.

Пример вызова метода:

```typescript
captchaWidget.hidePopup();
```

## {heading(Показать капчу)[id=reference-sdk-web-show-popup]}

Метод `captchaWidget.showPopup()` возвращает виджет капчи на экран. Прохождение и состояние проверки при этом не сбрасываются. Метод ничего не возвращает в ответе.

Когда невидимая проверка разворачивается в видимое задание, VK Капча SDK вызывает этот метод автоматически.

Пример вызова метода:

```typescript
captchaWidget.showPopup();
```

## {heading(Закрыть капчу)[id=reference-sdk-web-close]}

Метод `captchaWidget.close()` закрывает виджет капчи. Метод ничего не возвращает в ответе.

Пример вызова метода:

```typescript
captchaWidget.close();
```

## {heading(Снять капчу со страницы)[id=reference-sdk-web-destroy]}

Метод `captchaWidget.destroy()` убирает капчу со страницы и возвращает виджет в исходное состояние: после него на той же загрузке страницы можно смонтировать следующую капчу методом `captchaWidget.render()`. Метод ничего не возвращает в ответе.

Метод нужен одностраничным приложениям (SPA, Single Page Application), где экраны сменяются без перезагрузки страницы. В этом случае капча привязывается к жизненному циклу экрана: при появлении экрана вызывается метод `captchaWidget.render()`, при уходе с этого экрана — `captchaWidget.destroy()`. У каждого экрана своя CAPTCHA-сессия и своя ссылка. Если на следующем экране тоже вызывается метод `captchaWidget.render()` без предшествующего вызова `captchaWidget.destroy()`, promise-объект отклоняется с ошибкой `already_initialized`.

Учитывайте, что:

- Каждому экрану нужен свой экземпляр `CaptchaWidget`.

  Одновременно на странице должен работать только один экземпляр капчи. При переходе между экранами сначала вызовите `captchaWidget.destroy()` на текущем экземпляре, а затем создайте и смонтируйте новый.

- Ссылка для следующей капчи должна быть новой: капча-сессия расходуется первой же проверкой, поэтому запросите свежую ссылку методом `GET /captchaNotRobot.createSession`.

  Кешировать ссылку в состоянии приложения нельзя: на следующем экране капча смонтируется, но проверка вернет истекший токен. Запрашивайте ссылку в том же коде, который вызывает `captchaWidget.render()`.

- Обрабатывайте отклонение promise-объекта с ошибкой `destroyed`. 
  
  Метод `captchaWidget.destroy()` отклоняет незавершенные promise-объекты методов `captchaWidget.render()` и `captchaWidget.execute()` с ошибкой `destroyed`. В React StrictMode эффект в режиме разработки выполняется дважды, поэтому первый вызов `captchaWidget.render()` отклоняется всегда — в консоли это выглядит как необработанное отклонение promise-объекта.

- Перед вызовом `captchaWidget.render()` проверяйте, что экран еще активен.

  Между запросом ссылки и ответом бэкенда пользователь может уйти с экрана. Вызванный после этого `captchaWidget.destroy()` ничего не сделает, потому что капча еще не смонтирована, а вызванный следом `captchaWidget.render()` смонтирует ее на покинутом экране.

- О снятии капчи VK Капча SDK событий не отправляет.

Пример вызова метода:

```typescript
let captchaWidget: CaptchaWidget | undefined;
let isScreenActive = false;

// Экран появился. В React — эффект компонента, в котором стоит капча
async function mountCaptcha() {
    isScreenActive = true;
    captchaWidget = new CaptchaWidget();
    captchaWidget.on(CaptchaPublicEvents.SUCCESS, onSuccess);
    const { link } = await api.post('/api/captcha/session', { client });
    // Пользователь мог уйти с экрана, пока бэкенд отвечал
    if (!isScreenActive) {
        return;
    }
    // Уход с экрана до загрузки отклоняет promise-объект кодом destroyed
    await captchaWidget.render({ link, lang: 'ru', invisible: true }).catch(handleRenderError);
}

// Уход с экрана. В React — функция очистки того же эффекта
function unmountCaptcha() {
    isScreenActive = false;
    captchaWidget?.destroy();
}
```
