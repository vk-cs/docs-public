# {heading(Сети в Bare Metal)[id=bare-metal-network]}

Все серверы Bare Metal одного {linkto(../../../../tools-for-using-services/account/concepts/projects#tools-account-concepts-projects)[text=проекта]} находятся в собственной L2-сети, к которой подключены через {linkto(#bare-metal-network-nic-and-lag)[text=сетевые интерфейсы]}. Поверх этой сети создаются отдельные логические сегменты — {linkto(#bare-metal-network-vlan)[text=VLAN]}.

{note:info}
В сети Bare Metal не поддерживаются {linkto(../../../../networks/vnet/concepts/traffic-limiting#vnet-traffic-limiting-secgroups)[text=группы безопасности]}.
{/note}

## {heading(Сетевые интерфейсы и агрегирование каналов)[id=bare-metal-network-nic-and-lag]}

_Сетевые интерфейсы_ — физические Ethernet-порты. Их количество зависит от количества сетевых карт в конфигурации сервера, {linkto(../../instructions/manage-server#bare-metal-server-get-info)[text=получить]} информацию о сетевых интерфейсах можно на странице сервера на вкладке **Сеть**. Сетевой интерфейс может или быть самостоятельным участником сети, или входить в состав агрегированного сетевого интерфейса.

_Агрегированный сетевой интерфейс_ (Link Aggregation Group, LAG — агрегирование каналов) объединяет 2 и более сетевых интерфейса в один логический. Это позволяет увеличить общую пропускную способность подключения, а также обеспечить резервирование сети на уровне L2-канала, т.к. каждый сетевой интерфейс, участвующий в агрегировании каналов, подключается к двум разным коммутаторам. Пока сетевые интерфейсы объединены в один логический, использовать их по отдельности нельзя.

Агрегирование интерфейсов настраивается на двух сторонах:

- На стороне сетевой инфраструктуры Bare Metal от {var(cloud)}: порты независимых коммутаторов, к которым подключен сервер, объединяются в один канал с поддержкой LACP (Link Aggregation Control Protocol).
- В ОС на стороне сервера Bare Metal, чтобы пользоваться этим каналом, тоже нужно объединить физические сетевые интерфейсы в один логический. В Linux он называется `bond` и для него также поддерживается работа через LACP (Link Aggregation Control Protocol). С его помощью сервер и коммутаторы автоматически согласуют работу общего канала и отслеживают состояние отдельных линков. Без настройки в ОС интерфейсы продолжат работать по отдельности, и агрегированный интерфейс не заработает.

Каждый сетевой интерфейс, в т.ч. агрегированный, можно подключить к одному или нескольким VLAN.

## {heading(VLAN)[id=bare-metal-network-vlan]}

_VLAN_ (Virtual Local Area Network, стандарт [IEEE 802.1Q](https://www.ieee802.org/1/pages/802.1Q-2014.html)) — это технология, позволяющая создавать независимые и изолированные L2-сети, как если бы они были подключены к разным физическим сегментам сетевой инфраструктуры, например к разным коммутаторам. Устройства в рамках одного VLAN не видят трафик из других VLAN, в т.ч. и широковещательные запросы. Таким образом трафик сегментирован по разным VLAN, что позволяет раздельно работать с сетями разного назначения. Например, разделить клиентскую (production) и тестовую (development, stage) инфраструктуру или изолировать группы хостов разных проектов.

У каждого VLAN есть VLAN ID от `2` до `3999`, уникальный в рамках проекта {var(cloud)}.

Трафик VLAN передается через сетевой интерфейс одним из двух способов:

- С тегом (tagged): в Ethernet-кадр добавляется тег с VLAN ID, по которому устройства определяют, к какому VLAN относится кадр.
- Без тега (untagged): Ethernet-кадр не содержит VLAN ID, а принимающая сторона относит его к Native VLAN.

    _Native VLAN_ — VLAN, трафик которого передается через интерфейс без тега. Задается при {linkto(../../instructions/manage-net#bare-metal-network-config-nic-or-bond)[text=настройке сети]}, {linkto(../../instructions/manage-service#bare-metal-manage-service-order)[text=заказе]} нового сервера или {linkto(../../instructions/os-setup#bare-metal-os-setup)[text=установке]} ОС. Native VLAN присваивается обязательно и только один на каждый сетевой интерфейс.

VLAN в сети Bare Metal от {var(cloud)} бывают двух типов: `Sprut` и `L2Only`.
