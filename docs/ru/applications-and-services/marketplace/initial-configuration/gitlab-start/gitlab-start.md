# {heading(Развертывание GitLab CE)[id=gitlab-start]}

Вы можете хранить Git-репозитории, проводить ревью кода и запускать CI/CD-пайплайны с помощью сервиса GitLab CE. Подробнее о сервисе в [официальной документации GitLab](https://docs.gitlab.com/).

Сервис работает на одной ВМ. Раннер для CI/CD-пайплайнов уже подключен и доступен всем проектам.

{cut(Минимальные технические характеристики ВМ для сервиса)}

- **vCPU**: 4.
- **RAM**: 16 ГБ.
- Размер дисков:

  - **Системный диск**: не менее 20 ГБ.
  - **Диск с данными**: не менее 50 ГБ.

- **Сеть**:

  - ВМ должна иметь доступ в интернет.
  - Приватный DNS должен быть выключен.

{/cut}

Инструкция поможет развернуть сервис GitLab CE на ВМ в {var(cloud)}.

Используя GitLab CE, вы соглашаетесь с лицензионными соглашениями [Marketplace](https://cloud.vk.ru/docs/ru/start/legal/offer/private-special-conditions/policy-marketplace) и [GitLab CE](https://gitlab.com/gitlab-org/gitlab-foss/-/blob/master/LICENSE).

Чтобы развернуть сервис GitLab CE в проекте VK Cloud:

1. [Зарегистрируйтесь](https://cloud.vk.ru/docs/ru/intro/onboarding/account/create-account) и [перейдите](https://msk.cloud.vk.ru/app) в личный кабинет VK Cloud.
1. Настройте сеть, чтобы иметь доступ к сервису из интернета:

   1. {linkto(../../../../networks/vnet/instructions/net#vnet-net-add)[text=Создайте]} сеть с доступом в интернет, если это еще не сделано.
   1. В {linkto(../../../../networks/vnet/instructions/net#vnet-net-subnet-edit)[text=настройках подсети]}, где будут размещены ВМ с развернутым сервисом, отключите опцию **Приватный DNS**.

1. Перейдите в раздел **Магазин приложений**, на странице раздела нажмите кнопку **Все решения**.
1. На карточке сервиса **GitLab CE** нажмите кнопку **Подробнее**, затем кнопку **Подключить**.
1. На шаге **Параметры сервера** укажите параметры:

   - **Зона доступности**: выберите {linkto(../../../../start/concepts/architecture#architecture-az)[text=зону доступности]}, где будет запущена ВМ.
   - **Тип виртуальной машины**: выберите {linkto(../../../../computing/iaas/concepts/vm/flavor#iaas-flavor)[text=предустановленную конфигурацию ВМ]}. Для пилота и небольшой команды выберите шаблон с 4 ядрами и 16 ГБ оперативной памяти. Задачи CI/CD выполняются на этой же ВМ, поэтому при активной работе с пайплайнами выберите шаблон с 8 ядрами и 32 ГБ памяти или больше.
   - **Сеть**: выберите ранее созданную сеть с доступом в интернет и подсеть с отключенной опцией **Приватный DNS**.
   - **Тип системного диска** и **Размер системного диска**: оставьте значения по умолчанию.
   - **Тип диска**: выберите {linkto(../../../../computing/iaas/concepts/data-storage/disk-types#iaas-disk-types-list)[text=один из типов дисков]} — `HDD`, `SSD` или `High-IOPS SSD`.
   - **Размер диска данных**: укажите нужный размер диска ВМ в гигабайтах. Для пилота достаточно 50 ГБ. Для рабочей нагрузки выберите значение в два раза больше ожидаемого объема репозиториев, артефактов и образов: перед обновлением версии сервис сохраняет на этот диск резервную копию.

1. Нажмите кнопку **Следующий шаг**.
1. На шаге **Доступ** укажите параметры:

   - **Домен, сертификат и публичный адрес**: оставьте опцию включенной, чтобы открывать GitLab из интернета по доменному имени с доверенным сертификатом. Публичный IP-адрес оплачивается отдельно. Выключите опцию, если GitLab нужен только внутри сети проекта. После развертывания опцию изменить нельзя.
   - **Сеть клиентов**: укажите значение `subnet`, если компьютеры и серверы, которые работают с GitLab, находятся в той же подсети, что и ВМ с развернутым сервисом. Если они в другой подсети, укажите ее адрес, например `10.0.2.0/24`. {linkto(../../../../computing/iaas/concepts/data-storage/disk-types#iaas-disk-types-list)[text=Посмотреть]} адрес подсети можно в личном кабинете. Из сети клиентов доступны Git по SSH и Container Registry, а при выключенной опции **Домен, сертификат и публичный адрес** — и веб-интерфейс GitLab.
   - **Container Registry**: включите опцию, если нужно хранить Docker-образы в GitLab. Реестр работает только с доверенным сертификатом, поэтому ему нужна включенная опция **Домен, сертификат и публичный адрес**.

1. Нажмите кнопку **Следующий шаг**.
1. Ознакомьтесь со стоимостью инфраструктуры для развертывания сервиса и нажмите кнопку **Подключить тариф**.

   Начнется развертывание. Статус отображается в разделе **Магазин приложений** → **Мои сервисы**. Когда статус сменится на **Активный**, на почту придет письмо с одноразовой ссылкой на данные для доступа.

1. Перейдите по ссылке из письма и сохраните данные для доступа:

    - `productURL` — адрес веб-интерфейса GitLab;
    - `gitlabUser` и `gitlabPassword` — логин и пароль администратора GitLab;
    - `registryURL` — адрес Container Registry, если реестр включен;
    - `internalIP` и `externalIP` — внутренний и публичный IP-адреса ВМ;
    - `sshUser` и `sshKey` — логин и закрытый ключ для подключения к ВМ по SSH.

   {note:info}
   Если данные для доступа утрачены, {linkto(../../../../applications-and-services/marketplace/instructions/pr-instance-manage#marketplace-pr-instance-manage-update-access)[text=сгенерируйте]} новые.
   {/note}

1. Откройте `productURL` в браузере и войдите в GitLab с логином `gitlabUser` и паролем `gitlabPassword`.
