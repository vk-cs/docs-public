# {heading(Установка и настройка сервиса Valkey)[id=valkey-start]}

Сервис Valkey в {var(cloud)} — это высокопроизводительное хранилище данных в оперативной памяти, оптимизированное для сценариев, требующих мгновенного доступа к информации. Сервис подходит для реализации кеширования, управления сессиями пользователей, обработки очередей задач и работы со сложными структурами данных в реальном времени.

Valkey полностью совместим с протоколом и командной строкой Redis OSS 7.2, что позволяет мигрировать существующие решения или развернуть новые микросервисы без изменений в коде. Подробнее о сервисе в [официальной документации Valkey](https://valkey.io/topics/).

{cut(Минимальные требования к инфраструктуре)}

* **vCPU**: 2.
* **RAM**: 8 ГБ.
* Размер дисков:

   * **Системный диск**: не менее 30 ГБ.
   * **Диск с данными**: не менее 50 ГБ.

* **Сеть**:

  * ВМ должна иметь доступ в интернет.
  * Приватный DNS должен быть отключен.

{/cut}

Инструкция поможет развернуть сервис Valkey на выделенных виртуальных машинах в {var(cloud)} и настроить клиентское подключение к нему из приложения по TLS.

Используя сервис Valkey, вы соглашаетесь с лицензионными соглашениями [Marketplace VK Cloud](../../../../start/legal/offer/private-special-conditions/policy-marketplace) и [Valkey](https://github.com/valkey-io/valkey/blob/unstable/COPYING).

   1. {linkto(../../../../networks/vnet/instructions/net#vnet-net-add)[text=Создайте]} сеть с доступом в интернет, если это еще не сделано.

## {heading(1. Подключите сервис Valkey)[id=valkey-start-install]}

1. В [личном кабинете](https://msk.cloud.vk.com/app/) {var(cloud)} перейдите в раздел **Магазин приложений**.
1. Нажмите на карточку сервиса **Valkey**.

   Если на странице нет карточки сервиса **Valkey**, нажмите кнопку **Все решения** и найдите карточку в каталоге.

1. На странице с описанием сервиса нажмите кнопку **Подключить**.
1. На вкладке **Тарифные планы** выберите версию сервиса из списка.
1. Выберите подходящий тариф:

   - **Single** — одна ВМ, без репликации. В случае отказа узла или зоны сервис недоступен до восстановления ВМ. Подключение происходит напрямую через адрес узла. Подходит для разработки и тестирования.
   - **Sentinel** — три или пять ВМ (узлов) в разных зонах доступности, один из которых будет главным. Именно он принимает все запросы на создание, изменение и удаление данных, а остальные хранят полные копии этих данных. Если главный узел откажет, его роль перейдет к другому узлу. Подходит для организации кеша, сессий и очередей при условии что данные помещаются в память одной ВМ.
   - **Cluster** — шесть или девять ВМ (узлов) в разных зонах доступности. Если главный узел откажет, его роль перейдет к другому узлу. Данные распределяются между несколькими серверами (шардами). Копии каждого шарда хранятся в других зонах. Местоположение данных в кластере определяется по ключу. Подходит для хранения данных, которые не помещаются в память одной ВМ, или для горизонтального масштабирования. Работающие с таким кластером приложения должны поддерживать кластерный клиент.

1. Укажите параметры ВМ, на которых будет развернут сервис:

   {tabs}
   {tab(Single)}

   - **Тип виртуальной машины**: выберите конфигурацию ВМ из списка — от `2-8` до `16-64`, где первое число задает количество ядер, второе — объем памяти в гигабайтах. Для разработки и тестирования выберите `2-8`, для рабочей нагрузки — `4-16` или больше.
   - **Сеть**: выберите ранее созданную сеть с доступом в интернет и подсеть с отключенной опцией **Приватный DNS**.

   {/tab}
   {tab(Sentinel)}

   - **Количество узлов**: задайте количество виртуальных машин, которые система создаст для вашего кластера. Один из узлов будет главным (primary), остальные — реплики. Узлы распределяются по зонам `MS1`, `ME1` и `PA2`. На каждом из узлов будет запущен сервис мониторинга Sentinel. Укажите значение не менее `3`. Чтобы обеспечить отказоустойчивость при отказе двух узлов сразу, укажите значение `5`.
   - **Тип виртуальной машины**: выберите конфигурацию ВМ из списка — от `2-8` до `16-64`, где первое число задает количество ядер, второе — объем памяти в гигабайтах. Для разработки и тестирования выберите `2-8`, для рабочей нагрузки — `4-16` или больше.
   - **Сеть**: выберите ранее созданную сеть с доступом в интернет и подсеть с отключенной опцией **Приватный DNS**.

   {/tab}
   {tab(Cluster)}

   - **Количество узлов**: задайте количество виртуальных машин, которые система создаст для вашего кластера. Один из узлов будет главным (primary), остальные — реплики. Узлы распределяются по зонам `MS1`, `ME1` и `PA2`. На каждом из узлов будет запущен сервис мониторинга Sentinel. Укажите значение не менее `6`. Чтобы обеспечить отказоустойчивость при отказе двух шардов сразу, укажите значение `9`.
   - **Тип виртуальной машины**: выберите конфигурацию ВМ из списка — от `2-8` до `16-64`, где первое число задает количество ядер, второе — объем памяти в гигабайтах. Для разработки и тестирования выберите `2-8`, для рабочей нагрузки — `4-16` или больше.
   - **Сеть**: выберите ранее созданную сеть с доступом в интернет и подсеть с отключенной опцией **Приватный DNS**.

   {/tab}
   {/tabs}

1. Укажите параметры диска с данными:

   - **Размер диска**: укажите нужный размер диска ВМ в гигабайтах. Для хранения данных с учетом резервного копирования (RDB) диск должен быть в два раза больше объема данных в памяти. Если дополнительно требуется вести журнал операций (AOF), необходимый объем диска увеличивается до трех объемов памяти. Например, для типа ВМ `8-32` с журналом нужно около 70 ГБ для организации хранилища или 50 ГБ для кеша.
   - **Тип диска**: выберите {linkto(../../../../computing/iaas/concepts/data-storage/disk-types#iaas-disk-types-list)[text=один из типов диска]}. Для интенсивной записи выберите `High-IOPS SSD`.

1. Оставьте значения параметров системного диска по умолчанию.
1. Нажмите кнопку **Следующий шаг**.
1. Настройте параметры доступа:

   - **Сеть клиентов**: укажите значение `subnet`, чтобы открыть сервис только из выбранной подсети, либо задайте диапазон сети вида `10.20.0.0/16`, в которой работают приложения. {linkto(../../../../computing/iaas/concepts/data-storage/disk-types#iaas-disk-types-list)[text=Посмотреть]} адрес подсети можно в личном кабинете.
   - **Единый адрес через балансировщик** (только для тарифа **Sentinel**): включите опцию, если ваш код приложения не поддерживает механизм Sentinel. Тогда у сервиса будет один адрес, который всегда ведет на текущий главный узел. Балансировщик нагрузки для этого адреса оплачивается отдельно.

1. Настройте параметры Valkey:

   - **Сохранение на диск**: включите опцию, если нужно хранить данные на диске, а не в памяти. Если вы планируете использовать Valkey для организации кеша, отключите эту опцию.
   - **Журнал операций**: включите опцию, чтобы минимизировать риск потери данных. Журнал записывает каждую команду изменения в файл и синхронизируется с диском раз в секунду. Если же журнал отключен, система опирается только на периодические снимки, которые могут быть редки.

1. (Опционально) Включите опцию **Дополнительные настройки Valkey** и задайте дополнительные настройки памяти:

   - **Доля памяти под данные**: укажите долю оперативной памяти узла, отведенную под данные (например, `70%`). Остальная память узла уходит на соединения, репликацию и снимки. Если включено сохранение на диск, размер этого диска должен быть минимум в два раза больше указанного значения.
   - **Политика вытеснения**: выберите вариант действия при переполнении памяти сервера. Возможные значения:

      - `noeviction` — сервис ничего не удаляет, но отклоняет новые записи (подходит для организации хранилища);
      - `allkeys-lru` — сервис удаляет давно не использованные ключи (подходит для организации кеша);
      - `volatile`-варианты — сервис удаляет только ключи с установленным сроком жизни (подходит для хранения важных данных вместе с кешем).

      Подробнее обо всех вариантах политики управления ключами в [официальной документации сервиса Valkey](https://valkey.io/topics/lru-cache/).

   - **Запись только при живой реплике** (только для тарифа **Sentinel**): включите эту опцию, чтобы главный узел блокировал новые записи, если не может гарантировать их сохранение на репликах.

1. Нажмите кнопку **Следующий шаг**.
1. Ознакомьтесь со стоимостью инфраструктуры для развертывания сервиса и нажмите кнопку **Подключить тариф**.

   Начнется развертывание облачной инфраструктуры, и откроется страница свойств сервиса. Статус процесса будет отображаться также в разделе **Магазин приложений** → **Мои сервисы**.

   После успешного развертывания на вашу почту, привязанную к {var(cloud)}, придут сообщения:

   - уведомление со ссылкой на инстанс сервиса в личном кабинете {var(cloud)};
   - письмо с одноразовой ссылкой на данные для доступа к сервису.

1. Перейдите по одноразовой ссылке из письма и сохраните данные для доступа к сервису:

   {tabs}
   {tab(Single)}

   - `nodes` — список узлов Valkey.
   - `endpoint` — адрес узла.
   - `clusterCA` — сертификат центра сертификации кластера.
   - `adminUser` и `adminPassword` — учетная запись администратора.
   - `appUser` и `appPassword` — учетная запись приложений.
   - `monitoringUser` и `monitoringPassword` — учетная запись мониторинга.
   - `sshUser` — логин для SSH-доступа к ВМ.
   - `sshKey` — приватный SSH-ключ. Сохраните этот ключ в файле, например `valkey_ssh.pem`.

   {/tab}
   {tab(Sentinel)}

   - `nodes` — список узлов Valkey.
   - `endpoint` — адрес главного узла или единый адрес балансировщика, если включена опция **Единый адрес через балансировщик**.
   - `sentinelHosts` — список адресов ВМ, на которых запущены Sentinel-процессы.
   - `masterName` — имя главного узла (primary).
   - `sentinelPassword` — пароль от ВМ, на которых запущены Sentinel-процессы.
   - `clusterCA` — сертификат центра сертификации кластера.
   - `adminUser` и `adminPassword` — учетная запись администратора.
   - `appUser` и `appPassword` — учетная запись приложений.
   - `monitoringUser` и `monitoringPassword` — учетная запись мониторинга.
   - `sshUser` — логин для SSH-доступа к ВМ.
   - `sshKey` — приватный SSH-ключ. Сохраните этот ключ в файле, например `valkey_ssh.pem`.

   {/tab}
   {tab(Cluster)}

   - `nodes` — адреса узлов сервиса Valkey. Адреса указаны в параметре через запятую без пробелов.
   - `clusterCA` — сертификат центра сертификации кластера.
   - `adminUser` и `adminPassword` — учетная запись администратора.
   - `appUser` и `appPassword` — учетная запись приложений.
   - `monitoringUser` и `monitoringPassword` — учетная запись мониторинга.
   - `sshUser` — логин для SSH-доступа к ВМ.
   - `sshKey` — приватный SSH-ключ. Сохраните этот ключ в файле, например `valkey_ssh.pem`.

   {/tab}
   {/tabs}

   Если данные для доступа утрачены, {linkto(../../../../applications-and-services/marketplace/instructions/pr-instance-manage#marketplace-pr-instance-manage-update-access)[text=сгенерируйте]} новые.

## {heading(2. Проверьте подключение к сервису Valkey)[id=valkey-start-check]}

Для проверки подключения можно использовать любую ВМ с Linux в клиентской сети, например, ваш сервер приложения.

1. Установите утилиту `valkey-cli` на ВМ, с которой хотите подключиться к сервису, если это еще не сделано:

   {tabs}
   {tab(Ubuntu 24.04 и выше)}
   ```bash
   sudo apt install -y valkey-tools
   ```
   {/tab}
   {/tabs}

1. {linkto(../../../../computing/iaas/instructions/vm/vm-connect/vm-connect-nix#iaas-vm-connect-nix)[text=Подключитесь]} к этой ВМ по SSH.
1. Сохраните сертификат из письма в файл `~/valkey-ca.pem`:

    ```bash
    cat > ~/valkey-ca.pem <<'EOF'
    <СЕРТИФИКАТ>
    EOF
   ```

   Здесь `<СЕРТИФИКАТ>` — значение `clusterCA` из письма целиком, включая строки `BEGIN` и `END`.

1. Выполните операции записи и чтения в сервис Valkey:

   {tabs}
   {tab(Single)}

   1. Выполните операции записи в сервис Valkey:

      ```bash
      export REDISCLI_AUTH='<ПАРОЛЬ_ПРИЛОЖЕНИЯ>'
      valkey-cli --tls --cacert ~/valkey-ca.pem --user <ЛОГИН_ПРИЛОЖЕНИЯ> \
         -h <АДРЕС_УЗЛА> -p 6379 SET greeting hello
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — IP-адрес без порта из параметра `endpoint` из письма.
      - `SET greeting hello` — команда Valkey, которая сохраняет значение `hello` под ключом `greeting`.

      Ожидаемый ответ: `OK`.

   1. Выполните операции чтения с узла в сервисе Valkey:

      ```bash
      valkey-cli --tls --cacert ~/valkey-ca.pem --user <ЛОГИН_ПРИЛОЖЕНИЯ> \
         -h <АДРЕС_УЗЛА> -p 6379 GET greeting
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — IP-адрес без порта из параметра `endpoint` из письма.
      - `GET greeting` — команда Valkey, которая запрашивает значение ключа `greeting`. 

      Ожидаемый ответ: `"hello"`.

   {/tab}
   {tab(Sentinel)}

   1. Если опция **Единый адрес через балансировщик** отключена в сервисе Valkey, узнайте IP-адрес главного узла:

      ```bash
      REDISCLI_AUTH='<ПАРОЛЬ_SENTINEL>' valkey-cli --tls --cacert ~/valkey-ca.pem \
      -h <АДРЕС_SENTINEL> -p 26379 SENTINEL get-master-addr-by-name <ИМЯ_УЗЛА>
      ```

      Здесь:

      - `<ПАРОЛЬ_SENTINEL>` — значение `sentinelPassword` из письма.
      - `<АДРЕС_SENTINEL>` — любой адрес из `sentinelHosts` без порта из письма.
      - `<ИМЯ_УЗЛА>` — имя главного узла из параметра `masterName` из письма.

      Первая строка ответа — адрес главного узла.

   1. Выполните операции записи в сервис Valkey:

      ```bash
      export REDISCLI_AUTH='<ПАРОЛЬ_ПРИЛОЖЕНИЯ>'
      valkey-cli --tls --cacert ~/valkey-ca.pem --user <ЛОГИН_ПРИЛОЖЕНИЯ> \
         -h <АДРЕС_УЗЛА> -p 6379 SET greeting hello
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — адрес текущего главного узла из параметра `endpoint` из письма (если включена опция **Единый адрес через балансировщик**) или из вывода команды на шаге выше.
      - `SET greeting hello` — команда Valkey, которая сохраняет значение `hello` под ключом `greeting`.

      Ожидаемый ответ: `OK`.

   1. Выполните операции чтения с узла в сервисе Valkey:

      ```bash
      valkey-cli --tls --cacert ~/valkey-ca.pem --user <ЛОГИН_ПРИЛОЖЕНИЯ> \
         -h <АДРЕС_УЗЛА> -p 6379 GET greeting
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — адрес текущего главного узла из параметра `endpoint` из письма (если включена опция **Единый адрес через балансировщик**) или из вывода команды на шаге выше.
      - `GET greeting` — команда Valkey, которая запрашивает значение ключа `greeting`.

      Ожидаемый ответ: `"hello"`.

   {/tab}
   {tab(Cluster)}

   1. Выполните операции записи в сервис Valkey:

      ```bash
      export REDISCLI_AUTH='<ПАРОЛЬ_ПРИЛОЖЕНИЯ>'
      valkey-cli -c --tls --cacert ~/valkey-ca.pem --user app \
         -h <АДРЕС_УЗЛА> -p 6379 SET greeting hello
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — любой IP-адрес из параметра `nodes` из письма.
      - `-c` — ключ, с которым утилита `valkey-cli` сама переходит на узел, где хранится ключ.
      - `SET greeting hello` — команда Valkey, которая сохраняет значение `hello` под ключом `greeting`.

      Ожидаемый ответ: `OK`.

   1. Выполните операции чтения с узла в сервисе Valkey:

      ```bash
      valkey-cli -c --tls --cacert ~/valkey-ca.pem --user app \
         -h <АДРЕС_УЗЛА> -p 6379 GET greeting
      ```

      Здесь:

      - `<ПАРОЛЬ_ПРИЛОЖЕНИЯ>` — значение `appPassword` из письма.
      - `<ЛОГИН_ПРИЛОЖЕНИЯ>` — значение `appUser` из письма.
      - `<АДРЕС_УЗЛА>` — любой IP-адрес из параметра `nodes` из письма.
      - `-c` — ключ, с которым утилита `valkey-cli` сама переходит на узел, где хранится ключ.
      - `GET greeting` — команда Valkey, которая запрашивает значение ключа `greeting`.

      Ожидаемый ответ: `"hello"`.

   {/tab}
   {/tabs}

   Учетной записи `appUser` недоступны административные команды, например `CONFIG`, `FLUSHALL` и `KEYS`. Для них используйте `adminUser` и `adminPassword`.

## {heading(3. (Опционально) Подключите приложение)[id=valkey-start-check]}

1. Сохраните значение `clusterCA` в файл на сервере приложения, если это не сделано ранее.
1. Передайте параметры подключения клиенту Valkey в коде приложения. Далее приведены примеры для Python с библиотекой `redis` согласно выбранному тарифу. В других языках используйте клиент Redis или Valkey, который поддерживает TLS и вход по имени пользователя и паролю.
