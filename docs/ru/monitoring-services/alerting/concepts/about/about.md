# {heading(О сервисе)[id=alerting-about]}

Cloud Alerting — это сервис, который позволяет настроить уведомления о требующих внимания событиях в сервисах мониторинга {var(cloud)}. Уведомления помогают своевременно реагировать на изменение состояния облачных ресурсов и предотвращать сбои в работе ваших приложений.

Например, уведомление о росте загрузки процессора поможет определить, что ВМ перегружена задачами, а уведомление о назначении неизвестному пользователю роли администратора поможет вовремя обнаружить и пресечь нежелательный доступ к вашей инфраструктуре.

Cloud Alerting фиксирует наступление события с помощью триггеров, после чего отправляет уведомление по SMS или электронной почте.

Срабатывание триггера можно {linkto(../../instructions/triggers#alerting-triggers)[text=настроить]} по следующим источникам:

По значениям метрик сервиса {linkto(../../../monitoring/concepts/architecture#monitoring-architecture)[text=Cloud Monitoring]}. Метрики собираются с конкретного ресурса (например, ВМ или БД). Значения метрик можно получить с помощью запроса к {linkto(../../../../tools-for-using-services/api/api-spec/monitoring2-api#api-spec-monitoring2)[text=API]} мониторинга на языке PromQL.
По записям сервиса {linkto(../../../logging/concepts/about#logging-about)[text=Cloud Logging]}. Записи собираются с ресурсов внутри конкретного сервиса {var(cloud)} и источником данных для триггера служит этот сервис. Условие для триггера задается на {linkto(../../../logging/concepts/search-tools#logging-search-tools)[text=языке поисковых запросов]}.
По событиям сервиса {linkto(../../../event-log/concepts/about#event-log-about)[text=Cloud Audit]}. События собираются с управляющего слоя или слоя данных сервиса {var(cloud)}. Условие для триггера задается на {linkto(../../../logging/concepts/search-tools#logging-search-tools)[text=языке поисковых запросов]}.

Триггеры по значениям метрик позволяют отслеживать изменения числовых показателей ресурса, например, падение производительности ВМ или скорости доступа к БД. Триггеры по записям и событиям позволяют быстро реагировать на инциденты, получив уведомление о конкретном событии, зафиксированном в логах или журнале аудита. Такие триггеры полезны администраторам инфраструктуры и специалистам по безопасности для быстрого обнаружения аномалий и инцидентов без ручного разбора логов.
