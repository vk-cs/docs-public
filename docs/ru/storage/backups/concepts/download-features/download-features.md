# {heading(Перенос резервных копий дисков ВМ вне {var(cloud)})[id=backup-download-features]}

Файлы резервных копий дисков ВМ из Cloud Backup можно скачать и сохранить вне платформы {var(cloud)}. Это может быть полезно, если правила вашей компании требуют хранения данных вне сервиса, или если вы планируете восстановить их на другой платформе.

Скачать файлы копии можно двумя способами:

- {linkto(../../instructions/download-backup/download-backup-lk#backup-download-lk)[text=через личный кабинет]};
- {linkto(../../instructions/download-backup/download-backup-cli-api#backup-download-cli-api)[text=через OpenStack CLI и API]}.

Каждый запуск резервного копирования ВМ создает точку восстановления (checkpoint). В ней хранится по одной резервной копии на каждый диск ВМ. Если у ВМ несколько дисков, у каждого диска своя копия и своя цепочка копий, а каждый диск собирается в отдельный RAW-файл.

{note:err}
Не удаляйте резервные копии из Cloud Backup после скачивания.

Сервис {var(s3)}, в котором хранятся резервные копии, обеспечивает {linkto(../../../../start/concepts/architecture#architecture-fault-tolerance)[text=двойную репликацию данных]}. Это гарантирует их сохранность даже в случае критических сбоев в работе инфраструктуры. Используйте скачанные файлы как дополнительную страховку, но не рассматривайте их как полную замену сервису Cloud Backup.
{/note}

## {heading(Из чего состоит резервная копия)[id=backup-download-features-content]}

Каждая резервная копия диска — это объекты в системном {linkto(../../../../storage/s3/concepts/about#s3-concepts-about-bucket)[text=бакете]} `volumebackups-<ID_ПРОЕКТА>` с префиксом `<ID_КОПИИ>/`. Копия состоит из пяти файлов. Для сборки диска используются все пять:

[cols="1,3", options="header"]
|===
| Файл
| Назначение

| `content`
| Данные диска: сегменты до 16 МБ, каждый из которых сжат алгоритмом LZ4. Если сжатие не уменьшает размер, сегмент хранится как есть

| `object_segments`
| Карта, которая описывает, где каждый сжатый сегмент лежит в `content` (`object_offset`, `object_length`)

| `volume_segments`
| Карта, которая описывает, куда на диск записать разжатый сегмент (`volume_offset`, `volume_length`)

| `sha_list`
| Контрольные суммы SHA-256 блоков по 64 КБ для всего диска. Используются для инкрементальных копий и проверки сборки

| `volume_metadata`
| Свойства диска и копии: размер, ID
|===

Резервные копии бывают двух типов:

- Полная копия содержит все данные диска, для сборки достаточно ее пяти файлов.
- Инкрементальная копия содержит только участки диска, измененные с момента предыдущей копии: ее файлы `object_segments` и `volume_segments` описывают эти участки. Для сборки диска нужна вся цепочка: базовая полная копия и все инкрементальные копии после нее до нужной даты включительно. Без любой копии цепочки диск собрать нельзя.

Наличие инкрементальных копий зависит от {linkto(../../instructions/create-backup-plan#backup-plan-create)[text=настроек плана резервного копирования]}. {linkto(../../instructions/create-backup-copy#backup-copy-create)[text=Ручные копии]} всегда полные.

## {heading(Сохранность копий в хранилище)[id=backup-download-features-lost]}

Копии хранятся в двух разных {linkto(../../../../computing/iaas/concepts/avail-zone#iaas-avail-zone)[text=центрах обработки данных (ЦОД)]}, поэтому для утраты данных копии в хранилище {var(cloud)} оба ЦОД должны одновременно выйти из строя. Если это произошло, восстановление зависит от того, сохранена ли запись о копии в Cloud Backup:

- Запись о копии в сервисе сохранена, и у вас есть скачанные файлы. Пока запись о копии и ее метаданные не удалены, специалисты технической поддержки могут вернуть файлы в системный бакет, после чего копия восстанавливается штатно, вместе с параметрами ВМ и сетями. Для этого обратитесь в [техническую поддержку](/ru/contacts).
- Копия удалена и в сервисе, и в хранилище (например, вы удалили ее сами после скачивания). Восстановить ВМ вместе с параметрами и сетями из скачанных файлов нельзя.

## {heading(Ограничения)[id=backup-download-features-limits]}

- Сборка диска из резервной копии и развертывание вне облака — ручная процедура, которая выполняется вами самостоятельно вне {var(cloud)}.
- Параметры ВМ (например, шаблон конфигурации, сети, ключи) в файлах копии не хранятся. При развертывании вне {var(cloud)} опишите их заново.
- Загрузка скачанных файлов обратно в хранилище не создает запись о копии в сервисе: в личном кабинете она не появится, и восстановить ВМ из такой копии будет нельзя.
