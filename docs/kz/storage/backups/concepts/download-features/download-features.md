# {heading(ВМ дисктерінің резервтік көшірмелерін {var(cloud)} сыртына ауыстыру)[id=backup-download-features]}

{include(/kz/_includes/_translated_by_ai.md)}

Cloud Backup сервисіндегі ВМ дисктерінің резервтік көшірмелерінің файлдарын жүктеп алып, {var(cloud)} платформасынан тыс сақтауға болады. Бұл компанияңыздың ережелері деректерді сервистен тыс сақтауды талап етсе немесе оларды басқа платформада қалпына келтіргіңіз келсе пайдалы болуы мүмкін.

Көшірме файлдарын екі тәсілмен жүктеп алуға болады:

- {linkto(../../instructions/download-backup/download-backup-lk#backup-download-lk)[text=жеке кабинет арқылы]};
- {linkto(../../instructions/download-backup/download-backup-cli-api#backup-download-cli-api)[text=OpenStack CLI және API арқылы]}.

ВМ резервтік көшіруінің әрбір іске қосылуы қалпына келтіру нүктесін (checkpoint) жасайды. Онда ВМ-нің әр дискі үшін бір резервтік көшірме сақталады. Егер ВМ-де бірнеше диск болса, әр дискінің өз көшірмесі және өз көшірмелер тізбегі болады, ал әр диск жеке RAW файлына жиналады.

{note:err}
Жүктеп алғаннан кейін резервтік көшірмелерді Cloud Backup сервисінен жоймаңыз.

Резервтік көшірмелер сақталатын {var(s3)} сервисі {linkto(../../../../start/concepts/architecture#architecture-fault-tolerance)[text=деректерді екі есе репликациялауды]} қамтамасыз етеді. Бұл инфрақұрылым жұмысында күрделі ақаулар болған жағдайда да олардың сақталуына кепілдік береді. Жүктеп алынған файлдарды қосымша сақтандыру ретінде пайдаланыңыз, бірақ оларды Cloud Backup сервисін толық алмастыру деп санамаңыз.
{/note}

## {heading(Резервтік көшірме неден тұрады)[id=backup-download-features-content]}

Дисктің әрбір резервтік көшірмесі — `volumebackups-<ID_ПРОЕКТА>` жүйелік {linkto(../../../../storage/s3/concepts/about#s3-concepts-about-bucket)[text=бакетіндегі]} `<ID_КОПИИ>/` префиксі бар объектілер. Көшірме бес файлдан тұрады. Дискті жинау үшін бесеуі де пайдаланылады:

[cols="1,3", options="header"]
|===
| Файл
| Мақсаты

| `content`
| Диск деректері: көлемі 16 МБ-қа дейінгі сегменттер, олардың әрқайсысы LZ4 алгоритмімен сығылған. Егер сығу өлшемді азайтпаса, сегмент сол күйінде сақталады

| `object_segments`
| Әрбір сығылған сегменттің `content` ішінде қай жерде орналасқанын сипаттайтын карта (`object_offset`, `object_length`)

| `volume_segments`
| Ашылған сегментті дискіге қайда жазу керектігін сипаттайтын карта (`volume_offset`, `volume_length`)

| `sha_list`
| Бүкіл диск үшін 64 КБ блоктардың SHA-256 бақылау сомалары. Инкременттік көшірмелер үшін және жинауды тексеру үшін пайдаланылады

| `volume_metadata`
| Диск пен көшірменің сипаттамалары: өлшемі, ID мәндері
|===

Резервтік көшірмелер екі түрде болады:

- Толық көшірмеде диск деректерінің барлығы бар, жинау үшін оның бес файлы жеткілікті.
- Инкременттік көшірмеде алдыңғы көшірмеден кейін өзгерген диск аймақтары ғана бар: оның `object_segments` және `volume_segments` файлдары осы аймақтарды сипаттайды. Дискіні жинау үшін бүкіл тізбек қажет: негізгі толық көшірме және одан кейінгі қажетті күнді қоса алғандағы барлық инкременттік көшірмелер. Тізбектегі кез келген көшірмесіз дискіні жинау мүмкін емес.

Инкременттік көшірмелердің болуы {linkto(../../instructions/create-backup-plan#backup-plan-create)[text=резервтік көшіру жоспарының баптауларына]} байланысты. {linkto(../../instructions/create-backup-copy#backup-copy-create)[text=Қолмен жасалған көшірмелер]} әрқашан толық болады.

## {heading(Көшірмелердің қоймада сақталуы)[id=backup-download-features-lost]}

Көшірмелер екі түрлі {linkto(../../../../computing/iaas/concepts/avail-zone#iaas-avail-zone)[text=деректерді өңдеу орталықтарында (ДӨО)]} сақталады, сондықтан {var(cloud)} қоймасындағы көшірменің жоғалуы үшін екі ДӨО бір мезгілде істен шығуы керек. Егер бұл орын алса, қалпына келтіру көшірме туралы жазбаның Cloud Backup сервисінде сақталғанына байланысты:

- Көшірме туралы жазба сервисте сақталған және сізде жүктеп алынған файлдар бар. Көшірме туралы жазба мен оның метадеректері жойылмаған кезде техникалық қолдау мамандары файлдарды жүйелік бакетке қайтара алады, содан кейін көшірме ВМ параметрлерімен және желілермен бірге әдеттегідей қалпына келтіріледі. Ол үшін [техникалық қолдауға](/kz/contacts) жүгініңіз.
- Көшірме сервисте де, қоймада да жойылған (мысалы, жүктеп алғаннан кейін оны өзіңіз жойдыңыз). ВМ-ді параметрлерімен және желілерімен бірге жүктеп алынған файлдардан қалпына келтіру мүмкін емес.

## {heading(Шектеулер)[id=backup-download-features-limits]}

- Резервтік көшірмеден дискіні жинау және бұлттан тыс орналастыру — {var(cloud)} сыртында өзіңіз орындайтын қолмен жасалатын процедура.
- ВМ параметрлері (мысалы, конфигурация үлгісі, желілер, кілттер) көшірме файлдарында сақталмайды. {var(cloud)} сыртында орналастырған кезде оларды қайтадан сипаттаңыз.
- Жүктеп алынған файлдарды қоймаға қайта жүктеу сервисте көшірме туралы жазбаны жасамайды: ол жеке кабинетте көрінбейді және мұндай көшірмеден ВМ-ді қалпына келтіру мүмкін болмайды.
