# {heading(rclone көмегімен объектілік жадқа деректердің резервтік көшірмесін жасау)[id=rclone-backup-scenarios]}

{include(/kz/_includes/_translated_by_ai_kz.md)}

{var(s3)} қызметінің көмегімен нақты тапсырмаға сай құрал таңдап, деректердің резервтік көшірмесін жасауды ұйымдастыруға болады. Командалық жолдан жұмыс істеу үшін rclone сай келеді — бұл S3-үйлесімді жадтарды, жылдамдықпен шифрлауды және икемді сақтау саясаттарын қолдайтын утилита.

Мысал ретінде кейіннен мына деректер қолданылады:

- Бакет атауы: `backup-bucket`
- Өңір: `ru-msk`
- {var(s3)} эндпоинті: `https://hb.ru-msk.vkcloud-storage.ru`

## {heading(Дайындық қадамдар)[id=rclone-backup-scenarios-prepare]}

1. {var(s3)} қызметіне аккаунт жасаңыз, егер ол әлі жасалмаса:
   1. {var(cloud)} жеке кабинетіне [өтіңіз](https://msk.cloud.vk.ru/app).
   1. Жобаны таңдаңыз.
   1. **Object Storage** → **Аккаунты** бөліміне өтіңіз.
   1. **Аккаунт қосу** немесе **Қосу** түймесін басыңыз.
   1. Аккаунт атауын белгілеңіз.
   1. **Жасау** түймесін басыңыз.
   1. Ашылған терезеде қолжетімділік кілтінің идентификаторын (**Access Key ID**) және құпия кілтті (**Secret Key**) көшіріп, сақтаңыз.

      {note:warn}
      Терезе жабылғаннан кейін құпия кілтті қалпына келтіру мүмкін болмайды. Егер кілт жоғалса, жаңасын жасаңыз.
      {/note}

1. [AWS CLI](../../../../tools-for-using-services/cli/aws-cli) орнатылғанын және жасалған {var(s3)} аккаунтымен жұмыс істеуге конфигурацияланғанын тексеріңіз. Бұл объектілердің өмірлік циклін CLI арқылы басқаруды жоспарласаңыз қажет болады.
1. `backup-bucket` атауымен бакет {linkto(../../instructions/buckets/create-bucket#s3-instructions-create-bucket)[text=жасаңыз]}.
1. rclone утилитасын [ресми құжаттамаға](https://rclone.org/install/) сүйеніп орнатыңыз.

## {heading(1. {var(s3)}-пен жұмыс істеуге rclone-ды конфигурациялаңыз)[id=rclone-backup-scenarios-step1]}

1. rclone-ды интерактивті конфигурациялауды іске қосыңыз:

   ```console
   rclone config
   ```

1. Жаңа қосылым жасау үшін `n` (new remote) опциясын таңдап, параметрлерді белгілеңіз:

    * Қосылым атауын көрсетіңіз, мысалы `vkcloud`.
    * `s3` (Storage) жад түрін таңдаңыз.
    * Провайдер ретінде `Other` таңдаңыз (кез келген S3-үйлесімді провайдер).
    * Қосылым параметрлерін белгілеңіз.

    `~/.config/rclone/rclone.conf` файлындағы қорытынды конфигурация мынадай болуы тиіс:

    ```ini
    [vkcloud]
    type = s3
    provider = Other
    env_auth = false
    access_key_id = <ACCESS_KEY>
    secret_access_key = <SECRET_KEY>
    region = ru-msk
    endpoint = https://hb.ru-msk.vkcloud-storage.ru
    ```

    Мұнда:

    - `<ACCESS_KEY>` — {var(s3)} аккаунтын жасаған кезде алынған **Access Key ID** мәні.
    - `<SECRET_KEY>` — {var(s3)} аккаунтын жасаған кезде алынған **Secret Key** мәні.
    - `ru-msk` — аккаунттың өңір коды. Қазақстан өңірі үшін `kz-ast` қолданыңыз.
    - `https://hb.ru-msk.vkcloud-storage.ru` — Мәскеу өңірінің {var(s3)} қызметінің эндпоинті. Қазақстан өңірі үшін `https://hb.kz-ast.vkcloud-storage.ru` қолданыңыз.

1. Қосылымды мына команданы орындап тексеріңіз:

   ```console
   rclone lsd vkcloud:
   ```

   Шығарылымда жасалған `backup-bucket` бакеті пайда болуы тиіс.

## {heading(2. (Қалауыңызша) Трафикті оңтайландыру үшін фильтрлерді конфигурациялаңыз)[id=rclone-backup-scenarios-step2]}

Резервтік көшірме жасау кезінде уақытша және қажетсіз файлдарды алып тастауға болады, бұл берілетін деректер көлемін және операцияны орындау уақытын қысқартады. Ол үшін `filter.txt` фильтр файлын жасап, онда алып тастау қажет файлдарды көрсетіңіз:

```text
# filter.txt
- *.tmp
- node_modules/**
+ *
```

Бұл файлдың атауын жергілікті және қашықтағы жадты синхрондау командасын шақырғанда `--filter-from` флагымен көрсету қажет болады.

Файл атауының алдындағы `+` белгісі файлды резервтік көшірмеге енгізу қажет екенін, ал `-` белгісі — елемеу қажет екенін білдіреді. Жоғарыдағы файл мысалында фильтрлер мынадай жұмыс істейді:

* `.tmp`-мен аяқталатын барлық файлдарды алып тастау (кез келген ұяшықтау деңгейінде);
* `node_modules` қалтасын және оның барлық құрамын рекурсивті алып тастау;
* алдыңғы ережелерге сәйкес келмеген барлық қалғанын енгізу.

{note:info}
`--filter-from` ішіндегі фильтрлердің реті маңызды: rclone ережелерді жоғарыдан төмен қарай өңдейді. Сәйкес келген бірінші ереже файлдың енгізілетінін немесе алып тасталатынын анықтайды.
{/note}

Егер жағдай күрделі болса немесе фильтрлеуге арналған файлдар аз болса, оларды `sync` синхрондау командасында `--exclude` немесе `--include` флагтары арқылы тікелей көрсетуге болады.

## {heading(3. (Қалауыңызша) Деректерді жылдамдықпен шифрлауды конфигурациялаңыз)[id=rclone-backup-scenarios-step3]}

rclone утилитасы деректерді жадқа жібермес бұрын `crypt` типті қосылым арқылы шифрлауды қолдайды. Бұл бакетте серверлік шифрлау болмаса да, деректерді шифрланған түрде сақтауға мүмкіндік береді.

Жергілікті және қашықтағы жадты синхрондау кезінде шифрлауды конфигурациялау үшін:

1. rclone-ды интерактивті конфигурациялауды іске қосыңыз:

   ```console
   rclone config
   ```

1. Жаңа қосылым жасау үшін `n` (new remote) опциясын таңдап, параметрлерді белгілеңіз:

    * Шифрлаумен қосылым атауын көрсетіңіз, мысалы `vkcloud-encrypted`.
    * `crypt` типін таңдаңыз.
    * Қосылым көзі ретінде `vkcloud:backup-bucket` көрсетіңіз.
    * Шифрлауға арналған негізгі және қосымша құпиясөздерді белгілеңіз.

   `~/.config/rclone/rclone.conf` файлындағы қорытынды конфигурация мынадай болуы тиіс:

   ```ini
   [vkcloud-encrypted]
   type = crypt
   remote = vkcloud:backup-bucket
   password = <ПАРОЛЬ>
   password2 = <ПАРОЛЬ_СОЛЬ>
   ```

   Мұнда:

   * `vkcloud:backup-bucket` — қашықтағы жадқа толық жол, ол бұрын `rclone config` арқылы конфигурацияланған қашықтағы жадтың атауынан және VK Object Storage қызметіндегі бакеттің (жадтың) атауынан тұрады.
   * `<ПАРОЛЬ>` — шифрланған құпиясөз.
   * `<ПАРОЛЬ_СОЛЬ>` — қосымша шифрланған құпиясөз, оны rclone утилитасының алгоритмі қорытынды криптографиялық кілтті есептеу үшін негізгі құпиясөзбен біріктіреді.

   {note:warn}
   Негізгі және қосымша құпиясөздерді қалпына келтіру мүмкін емес. Оларды қауіпсіз жерде сақтаңыз — олар болмаса деректерді шешу мүмкін болмайды.
   {/note}

## {heading(4. (Қалауыңызша) Резервтік көшірмелерді сақтау саясаттарын конфигурациялаңыз)[id=rclone-backup-scenarios-step4]}

Ескірген резервтік көшірмелерді автоматты түрде жою үшін rclone-ның кірістірілген мүмкіндіктерін қолданыңыз:

1. Берілген күн санынан ескі файлдарды жойыңыз:

   ```console
   rclone delete vkcloud:backup-bucket --min-age 30d
   ```

Мұнда:

   * `vkcloud:backup-bucket` — қашықтағы жадқа толық жол, ол бұрын `rclone config` арқылы конфигурацияланған қашықтағы жадтың атауынан және VK Object Storage қызметіндегі бакеттің (жадтың) атауынан тұрады.
   * `--min-age` — файлдарды жасы бойынша фильтрлеу опциясы, ол берілген уақыттан ескі емес файлдарды, мысалы 30 күннен ескі емес, көшіруге немесе өңдеуге мүмкіндік береді.

Алдыңғы нұсқаларын сақтай отырып инкременталды бэкаптар жасау үшін `--backup-dir` флагын `sync` синхрондау командасында тікелей қолданыңыз.

## {heading(5. Резервтік көшірме жасаудың жұмыс істеуін тексеріңіз)[id=rclone-backup-scenarios-check]}

1. Тесттік файл жасаңыз:

   ```console
   mkdir -p /data
   echo "test backup data" > /data/test-file.txt
   ```

1. Резервтік көшірмелерді сақтаудың берілген фильтрлері және конфигурацияланған саясаттарымен шифрлау арқылы орындаңыз:

   ```console
   rclone sync /data vkcloud-encrypted:/current \
     --filter-from filter.txt \
     --verbose \
     --backup-dir vkcloud:backup-bucket/archive/$(date +%Y-%m-%d)
   ```

   Мұнда:

      * `/data` — деректерді тасымалдау қажет көз.
      * `vkcloud-encrypted:/current` — қашықтағы жадтың (VK Object Storage) `/current` қалтасына деректерді шифрлаумен қосылу.
      * `--filter-from filter.txt` — синхрондау кезінде деректерді фильтрлеу ережелері бар фильтр файлы.
      * `--backup-dir` — `sync` командасының мінез-құлқын анықтаудың опциясы: әр іске қосылғанда `current` қалтасындағы файлдардың ағымдағы нұсқасы `archive/<ДАТА>` қалтасына ауыстырылады, ал жаңа файлдар `current` қалтасына жүктеледі.
      * `--verbose` — егжей-тегжейлі шығарылымды қосу опциясы: файл атаулары, тасымалдау статусы, өткізіп жіберу, қателер, статистика және ағындар бойынша прогресс.

   {cut(Команда шығарылымының мысалы)}

   ```console
   Transferred:        16 B / 16 B, 100%, 0 B/s, ETA -
   Transferred:            1 / 1, 100%
   Elapsed time:         0.5s
   ```

   {/cut}

1. Файлдың бакетте пайда болғанын тексеріңіз:

   ```console
   rclone ls vkcloud-encrypted:
   ```

   Шығарылымда `test-file.txt` файлы болуы тиіс.

1. Бакеттегі деректердің шифрланғанын тексеріңіз — VK Object Storage бакетіндегі объектілер тізімін тікелей шығарыңыз:

   ```console
   rclone ls vkcloud:backup-bucket
   ```

   Файл атаулары мен олардың құрамы түпнұсқадан өзгеше болуы тиіс, себебі `crypt` атауларды да, деректерді де шифрлайды.

1. Файлды резервтік көшірмеден қалпына келтіріңіз:

   ```console
   mkdir -p /restored-data
   rclone copy vkcloud-encrypted:test-file.txt /restored-data/
   ```

1. Қалпына келтірілген файлдың құрамын тексеріңіз:

   ```console
   cat /restored-data/test-file.txt
   ```

   Шығарылымда мынау болуы тиіс: `test backup data`.
