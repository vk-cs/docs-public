Сіз {var(cloud)} платформасында орналастырылған кезінде image-based қолданбаларыңыздың инстанстарына SSL-сертификаттарды автоматты түрде орнатуға және орнатылған SSL-сертификаттарды уақытылы жаңартуға болады. Бұл қолданбаларыңызға пайдаланушылармен дер алмасу үшін қорғалған HTTPS-хаттамасын пайдалануға мүмкіндік береді.

Төменде мысалда [SSL-сертификаттарды басқару жүйесін](/kz/tools-for-using-services/vendor-account/concepts/ssl-cert-concept) image-based қолданбаға қалай интеграциялау көрсетілген.

## {heading(Дайындық қадамдары)[id=preparatory_steps]}

{include(/kz/_includes/_translated_by_ai_kz.md)}

Егер бұрын жасалмаса, image-based қолданбаның инстанстары орналасатын доменді тіркіңіз.

## {heading(1. Қолданба инстансының ВМ бейнесін дайындаңыз)[id=adjust_vm_image]}

Image-based қолданба орнатылған ВМ [бейнесін дайындау](/kz/tools-for-using-services/vendor-account/manage-apps/ibservice_add/ib_image_create) кезінде:

1. SSL-сертификат файлын және оның жеке кілті бар файлды сақтау үшін директория жасаңыз.

   Егер ВМ-ге бірнеше қолданба және олар үшін SSL-сертификаттар орнатылатын болса, қауіпсіздікті арттыру үшін әр қолданба үшін бөлек директория жасау ұсынылады.

1. (Міндетті емес) SSL-сертификат файлдарына және оның жеке кілтіне қолжетімділікті конфигурациялаңыз:

   1. Бұл файлдардың иесі болатын пайдаланушыны жасаңыз.
   1. SSL-сертификат файлдары және оның жеке кілті үшін пайдаланушылар тобын жасаңыз.
   1. Пайдаланушы мен топқа SSL-сертификат файлдарына, оның жеке кілтіне, сондай-ақ олар орналасатын директорияға қолжетімділік құқықтарын беріңіз.

      Қауіпсіздікті арттыру үшін қажеттен артық құқық беруді ұсынбаймыз. Бұл жағдайда келесі қолжетімділік құқықтарын орнату жеткілікті:

      - директория үшін — `755` (иесі шексіз қолжетімдікке ие, ал топ және қалған пайдаланушылар — тек оқу және орындау құқықтарына ие);
      - файлдар үшін — `644` (иесі оқу және жазу құқықтарына ие, ал топ және қалған пайдаланушылар — тек оқу құқығына ие).

1. (Міндетті емес) SSL-сертификат жаңартылған сайын инстанстың ВМ-інде қандай әрекеттер орындалуы қажет екенін көрсетіңіз:

   1. Қажетті әрекеттері бар bash-скрипт дайындаңыз және скрипт файлын ВМ бейнесіне орналастырыңыз.
   1. Егер SSL-сертификаттың иесі-пайдаланушысы жасалған болса, оған скрипт орналасқан директорияға қолжетімділік және скриптті орындау құқығын беріңіз.
   1. Скрипт дұрыс орындалатынын тексеріңіз.

## {heading(2. Қолданбаның Terraform манифестін дайындаңыз)[id=adjust_manifest]}

Қолданба инстансын орналастыру инфрақұрылымының сипаттамасы бар [Terraform манифестіне](/kz/tools-for-using-services/vendor-account/manage-apps/ibservice_add/tf_manifest/tf_manifest_steps) [ivkcs_cert ресурсын](/kz/tools-for-using-services/vendor-account/manage-apps/ivkcs/ivkcs_resources/ivkcs_cert) қосыңыз.

{cut(Негізгі баптаулары бар ресурс мысалы)}

Мысалда келтірілген ресурс конфигурациясы:

- `example.com` домені үшін SSL-сертификат жасайды.
- SSL-сертификат пен оның жеке кілтін `/etc/ssl/certs/` директориясына орналастырады.
- SSL-сертификат жаңартылған сайын `/opt/scripts/reload_nginx.sh` скриптін орындайды.

```hcl
resource "ivkcs_cert" "web_cert" {
  uuid              = var.instance_uuid
  domain            = "example.com"
  path_cert         = "/etc/ssl/certs/"
  renewal_hook_path = "/opt/scripts/reload_nginx.sh"
}
```

Мұнда:

- `uuid` — image-based қолданба инстансының идентификаторы.
- `domain` — сіздің image-based қолданбаңыздың инстанстары орналасатын және ол үшін SSL-сертификат шығарылатын доменнің FQDN мекенжайы.
- `path_cert` — SSL-сертификат файлы және оның жеке кілті бар файл сақталатын директорияға жол.
- `renewal_hook_path` — SSL-сертификат жаңартылғаннан кейін орындалатын скрипті бар директорияға жол.

{/cut}

{cut(Кеңейтілген баптаулары бар ресурс мысалы)}

Мысалда келтірілген ресурс конфигурациясы:

- `secure.example.com` домені үшін SSL-сертификат жасайды.
- SSL-сертификат пен оның жеке кілтін `/opt/app/ssl/` директориясына орналастырады.
- SSL-сертификат жаңартылған сайын `/opt/app/scripts/restart_service.sh` скриптін орындайды.
- SSL-сертификат файлдарының және оның жеке кілтінің иесі етіп `nginx` пайдаланушысын тағайындайды.
- SSL-сертификат файлдары және оның жеке кілті үшін `ssl-cert` тобын тағайындайды.
- SSL-сертификатпен операциялар үшін тайм-ауттарды орнатады.

```hcl
resource "ivkcs_cert" "secure_cert" {
  uuid              = var.instance_uuid
  domain            = "secure.example.com"
  path_cert         = "/opt/app/ssl/"
  renewal_hook_path = "/opt/app/scripts/restart_service.sh"
  cert_files_owner  = "nginx"
  cert_files_group  = "ssl-cert"

  timeouts {
    create = "30m"
    update = "15m"
    delete = "5m"
  }
}
```

Мұнда:

- `uuid` — image-based қолданба инстансының идентификаторы.
- `domain` — сіздің image-based қолданбаңыздың инстанстары орналасатын және ол үшін SSL-сертификат шығарылатын доменнің FQDN мекенжайы.
- `path_cert` — SSL-сертификат файлы және оның жеке кілті бар файл сақталатын директорияға жол.
- `renewal_hook_path` — SSL-сертификат жаңартылғаннан кейін орындалатын скрипті бар директорияға жол.
- `cert_files_owner` — SSL-сертификат файлдарының және оның жеке кілтінің иесі-пайдаланушы.
- `cert_files_group` — SSL-сертификат файлдары және оның жеке кілті үшін пайдаланушылар тобы.
- `timeouts.create` — SSL-сертификатты жасау тайм-ауты.
- `timeouts.update` — SSL-сертификатты жаңарту тайм-ауты.
- `timeouts.delete` — SSL-сертификатты жою тайм-ауты.
