## {heading(1. Дереккөздер тобының сипаттамасы бар файлды құрыңыз)[id=terraform-cdn-file]}

Дереккөздер тобы контентті орналастыруға және жеткізуге жауап беретін ішкі серверлерді басқарады. CDN-ресурсі үшін топ құрып, оған кемінде бір дереккөз қосу қажет. Сенімділік пен ақауға төзімділікті арттыру үшін топқа бірнеше дереккөз қосыңыз.

Terraform конфигурация файлын `cdn.tf` құрып, оған мына мазмұнды қосыңыз:

{include(../../../../_includes/_cdn_tf.md)[tags=origin]}

Мұнда:

- `name` — дереккөздер тобының атауы. Міндетті параметр.
- `origins` — дереккөздердің тізімі.
- `source` — дереккөздің IP-мекенжайы немесе домені және порт (пайдаланушы порты қолданылған жағдайда). Міндетті параметр.
- `enabled` — дереккөздің қолжетімділігі:

  - `enabled = true` немесе параметр көрсетілмеген — дереккөз қосулы;
  - `enabled = false` — дереккөз өшірулі.

- `backup` — резервтік {linkto(../../../../networks/cdn/concepts/origin-groups#cdn-origin-groups)[text=дереккөз түрі]} белгісі (дереккөз деңгейінде орнатылады):

  - `backup = true` — дереккөз резервтік болып табылады;
  - `backup = false` немесе параметр көрсетілмеген — дереккөз белсенді болып табылады.

- `use_next` — {linkto(../../../../networks/cdn/concepts/origin-groups#cdn-origin-groups)[text=тізімдегі келесі дереккөзді]} пайдалану (бүкіл топ деңгейінде орнатылады):

  - `use_next = true` — CDN-сервер контентті бірінші белсенді дереккөзден сұрайды. 4XX немесе 5XX диапазонындағы HTTP-статусымен жауап алған жағдайда CDN-сервер тізім бойымен төмен қарай жылжып, қалған дереккөздерден контентті сұрайды, олардың түріне қарамастан.
  - `use_next = false` немесе параметр көрсетілмеген — CDN-сервер алдымен белсенді дереккөздердің бірінен контентті сұрайды. Белсенді дереккөзден 5XX диапазонындағы HTTP-статусымен жауап келсе, CDN-сервер резервтік дереккөздердің бірінен контентті сұрайды. Белсенді немесе резервтік дереккөзден 4XX диапазонындағы HTTP-статусымен жауап келген жағдайда CDN-сервер тұтынушыға қатені қайтарады.

## {heading(2. (Міндетті емес) Жобаға шилдингті қосыңыз)[id=terraform-cdn-shielding]}

Дереккөздің шилдингі дереккөзді жоғары жүктемелерден қорғауға мүмкіндік береді. Бұл үшін пайдаланушылардың барлық сұрауларын жинайтын және қажетті контент өзінің кешінде болмаса, оларды дереккөзге біртіндеп жіберетін прекеш-сервер қолданылады.

Егер шилдингті пайдалануды жоспарламасаңыз, {linkto(#terraform-cdn-ssl)[text=SSL-сертификат қосуға]} өтіңіз.

CDN-ресурсінің конфигурациясына шилдингті қосу үшін қолжетімді прекеш-серверлердің тізімін алып, контент тұтынушыларына жақынын таңдаңыз.

1. Terraform конфигурация файлын `shieldings.tf` құрып, оған мына мазмұнды қосыңыз:

   ```hcl

   data "vkcs_cdn_shielding_pops" "pops" {}

   output "shielding_locations" {
       value = data.vkcs_cdn_shielding_pops.pops.shielding_pops
   }
   ```

1. Terraform конфигурация файлдарын бір директорияға орналастырыңыз:

   - `vkcs_provider.tf`;
   - `shieldings.tf`.

1. Осы директорияға өтіңіз.
1. Өзгерістерді қолданыңыз:

   ```console
   terraform apply
   ```

   Жауапта қолжетімді прекеш-серверлер туралы ақпарат қайтарады.

   Жауап мысалы:

   ```hcl
   shielding_locations = tolist([
     {
       "city" = "Moscow-Megafon"
       "country" = "Russia"
       "datacenter" = "mgf"
       "id" = 138
     },
   ])
   ```

   Мұнда:

   - `city`, `country` — прекеш-сервердің қатысу нүктелері орналасқан қала мен ел.
   - `datacenter` — прекеш-сервер орналасқан ДК (дата-центр).
   - `id` — қатысу нүктесінің идентификаторы.

1. Прекеш-сервердің қатысу нүктесін таңдап, оның деректерін CDN-ресурсінің конфигурация файлына қосыңыз. Бұл үшін `cdn.tf` файлын ашып, оған мына мазмұнды қосыңыз:

   {include(../../../../_includes/_cdn_tf.md)[tags=shielding]}

## {heading(3. (Міндетті емес) Жобаға SSL-сертификатты қосыңыз)[id=terraform-cdn-ssl]}

HTTPS протоколы арқылы контент жеткізгенде SSL-сертификаттар қолданылады. Өз SSL-сертификатыңызды қоса аласыз, [Let's Encrypt](https://letsencrypt.org/ru/) тегін сертификатын пайдалана аласыз немесе SSL-сертификатын мүлде пайдаланбасаңыз, контент HTTP протоколы арқылы жеткізіледі.

Егер Let's Encrypt сертификатын пайдалануды немесе SSL-сертификатын мүлде пайдаланбауды жоспарласаңыз, {linkto(#terraform-cdn-cdn)[text=CDN-ресурсін қосуға]} өтіңіз.

1. `certificate.pem` ашық бөлімі және `private-key.key` жабық бөлімі бар SSL-сертификатыңыздың файлдарын ресурстарды құратын директорияға орналастырыңыз.
1. Файлдарда сертификаттың барлық жолдары бар екенін тексеріңіз.
1. `cdn.tf` файлын ашып, оған мына мазмұнды қосыңыз:

   {include(../../../../_includes/_cdn_tf.md)[tags=ssl]}

   Мұнда:

   - `name` — SSL-сертификатының атауы.
   - `certificate` — сертификаттың ашық бөлімі бар файлдың жолы. Сертификаттың ашық бөлімінің барлық жолдары файлда болуы тиіс.
   - `private_key` — сертификаттың жабық бөлімі бар файлдың жолы. Сертификаттың жабық бөлімінің барлық жолдары файлда болуы тиіс.

   Үш параметрдің бәрі міндетті.

## {heading(4. CDN-ресурсінің сипаттамасын қосыңыз)[id=terraform-cdn-cdn]}

`cdn.tf` файлын ашып, оған мына мазмұнды қосыңыз:

{include(../../../../_includes/_cdn_tf.md)[tags=cdn]}

Мұнда:

- `cname` — контент CDN көмегімен жеткізілетін доменнің FQDN-і. Міндетті параметр.

  FQDN-ге түбірлік домен атауын қоспаңыз: `cdn.example.com` түріндегі жазба рұқсат етіледі, бірақ `cdn.example.com.` — рұқсат етілмейді. CDN үшін қосымша домендерді қосу үшін оларды `secondary_hostnames` параметрінде көрсетіңіз.

- `origin_group` — CDN-ресурсі үшін дереккөздер тобының идентификаторы. Идентификаторды конфигурациялық файлда көрсетуге, деректер көзінен немесе ресурс ішінен алуға болады. Міндетті параметр.

  {cut(Мысалдар)}

    - `origin_group = vkcs_cdn_origin_group.origin_group.id`: дереккөздер тобының идентификаторы `vkcs_cdn_origin_group` ресурсы құрылғаннан кейін алынады.
    - `origin_group = data.vkcs_cdn_origin_group.origin_group.id`: топтың идентификаторы `vkcs_cdn_origin_group` деректер көзінен алынады.
    - `origin_group = "266524"`: {var(cloud)} жеке кабинетіндегі {linkto(../../../../networks/cdn/instructions/manage-origin-groups#cdn-manage-origin-groups-list)[text=дереккөздер тобының тізімінен]} алынған идентификатор көрсетілген.

  {/cut}

- `active` — ресурстің қолжетімділігі:

  - `active = true` немесе параметр көрсетілмеген — CDN-ресурсі `Белсенді` күйіне өтеді, контент тұтынушыларға жеткізіледі;
  - `active = false` — CDN-ресурсі `Тықылдатылған` күйіне өтеді, контент тұтынушыларға жеткізілмейді.

- `options` — CDN-ресурсінің баптаулары. Қолжетімді барлық баптаулардың сипаттамасы [VKCS-провайдерінің құжаттамасында](https://docs.comcloud.xyz/providers/vk-cs/vkcs/latest/docs/resources/cdn_resource) келтірілген.
- `origin_protocol` — дереккөзбен өзара іс-қимыл протоколы:

  - `"http"` немесе параметр көрсетілмеген — дереккөздегі контент тек HTTP арқылы (80 порт) қолжетімді немесе дереккөз HTTPS-тен HTTP-ға қайта бағыттауды қолдайды.
  - `"https"` — дереккөздегі контент тек HTTPS арқылы (443 порт) қолжетімді немесе дереккөз HTTP-дан HTTPS-ке қайта бағыттауды қолдайды.
  - `"http, https"` — дереккөздегі контент HTTP және HTTPS арқылы қолжетімді. Бұл жағдайда CDN-ресурсінен дереккөзге сұрауда соңғы пайдаланушының сұрау протоколы сақталады. Сонымен қатар CDN-ресурсінің кешінде әр протокол үшін файлдың екі нұсқасы сақталады.

- `shielding` — CDN-ресурсі үшін дереккөздің шилдингін қосу. 

  - `enabled` — шилдингті қосу: `true` (қосулы) немесе `false` (өшірулі).
  - `pop_id` — шилдингтің қатысу нүктесінің идентификаторы. Осы мысалда идентификатор `vkcs_cdn_shielding_pop` деректер көзінен алынады. Оны тікелей конфигурацияда да көрсетуге болады. Мысал: `pop_id = 138`.

    Егер дереккөздің шилдингін қоспасаңыз, параметрлер блогын конфигурациядан өшіріңіз.

- `ssl_certificate` — HTTPS протоколы арқылы контент жеткізуге арналған SSL-сертификаты:

  - `type` — SSL-сертификатының түрі. Қолжетімді мәндер:

    - `"not_used"` — SSL-сертификаты пайдаланылмайды.
    - `"own"` — пайдаланушы сертификаты қосылады.
    - `"lets_encrypt"` — [Let's Encrypt](https://letsencrypt.org/ru/) тегін сертификаты қосылады. Сертификат шығару үшін CDN-ресурсі белсенді болуы тиіс (`active = true`). Сертификат CDN-ресурсі құрылғаннан кейін, сервер-дереккөздер қолжетімді болып, жеке домендерге арналған CNAME-жазбаларына қатысты өзгерістер DNS-те таралғанда жасалады. Әдетте бұған 30 минутқа дейін уақыт кетеді.

  - `id` — CDN-ресурсіне байланыстырылған SSL-сертификатының идентификаторы. Идентификатор `type = "own"` болған жағдайда көрсетілуі тиіс. Келтірілген `cdn.tf` файлында идентификатор бұрын қосылған `vkcs_cdn_ssl_certificate` ресурсынан алынады.

## {heading(5. Қажетті ресурстарды Terraform көмегімен құрыңыз)[id=terraform-cdn-resource]}

1. Terraform конфигурация файлдарын SSL-сертификатының файлдарымен бір директорияға орналастырыңыз:

   - `vkcs_provider.tf`;
   - `cdn.tf`.

1. Осы директорияға өтіңіз.
1. Конфигурациялық файлдар дұрыс және қажетті өзгерістер бар екеніне көз жеткізіңіз:

   ```console
   terraform validate && terraform plan
   ```

1. Өзгерістерді қолданыңыз:

   ```console
   terraform apply
   ```

   Растау сұралғанда `yes` енгізіңіз.

1. Операцияның аяқталуын күтіңіз.

## {heading(Конфигурацияның қолданылуын тексеріңіз)[id=terraform-cdn-check]}

Ресурстар сәтті құрылғанына көз жеткізіңіз:

1. {var(cloud)} жеке кабинетіне [өтіңіз](https://cloud.vk.ru/app/).
1. **CDN** → **CDN-ресурстары** бөліміне өтіңіз. CDN-ресурсі құрылғанына көз жеткізіңіз.
1. **CDN** → **Дереккөздер топтары** бөліміне өтіңіз. Дереккөздер топтары құрылғанына көз жеткізіңіз.
1. **CDN** → **SSL-сертификаттар** бөліміне өтіңіз. SSL-сертификаты жобаға қосылғанына көз жеткізіңіз.

## {heading(Пайдаланылмайтын ресурстарды өшіріңіз)[id=terraform-cdn-delete]}

Егер Terraform көмегімен құрылған ресурстар енді қажет болмаса, оларды өшіріңіз:

1. Terraform конфигурация файлдары бар директорияға өтіңіз.
1. Команданы орындаңыз:

   ```console
   terraform destroy
   ```

   Растау сұралғанда `yes` енгізіңіз.

1. Операцияның аяқталуын күтіңіз.
