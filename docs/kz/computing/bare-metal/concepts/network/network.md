## {heading(Желілік интерфейстер және арналарды агрегациялау)[id=bare-metal-network-nic-and-lag]}

_Желілік интерфейстер_ — физикалық Ethernet порттары. Олардың саны сервер конфигурациясындағы желілік карталардың санына байланысты. Желілік интерфейстер туралы ақпаратты сервер бетіндегі **Желі** қойындысынан {linkto(../../instructions/manage-server#bare-metal-server-get-info)[text=алуға]} болады. Желілік интерфейс не желінің дербес қатысушысы болуы, не агрегацияланған интерфейстің құрамына кіруі мүмкін.

_Агрегацияланған интерфейс_ (Link Aggregation Group, LAG — арналарды агрегациялау) 2 немесе одан көп желілік интерфейсті бір логикалық интерфейске біріктіреді. Бұл қосылымның жалпы өткізу қабілетін арттыруға, сондай-ақ L2 арна деңгейінде желіні резервтеуді қамтамасыз етуге мүмкіндік береді, өйткені арналарды агрегациялауға қатысатын әрбір желілік интерфейс екі түрлі коммутаторға қосылады. Желілік интерфейстер бір логикалық интерфейске біріктірілген кезде оларды бөлек пайдалануға болмайды.

Интерфейстерді агрегациялау екі жақта бапталады:

- {var(cloud)} Bare Metal желілік инфрақұрылымы жағында: сервер қосылған тәуелсіз коммутаторлардың порттары LACP (Link Aggregation Control Protocol) қолдауымен бір арнаға біріктіріледі.
- Bare Metal сервері жағындағы ОЖ-да: осы арнаны пайдалану үшін физикалық желілік интерфейстерді де бір логикалық интерфейске біріктіру қажет. Linux-та ол `bond` деп аталады және ол үшін де LACP (Link Aggregation Control Protocol) арқылы жұмыс істеуге қолдау көрсетіледі. Оның көмегімен сервер мен коммутаторлар ортақ арнаның жұмысын автоматты түрде келіседі және жеке линктердің күйін бақылайды. ОЖ-да баптау болмаса, интерфейстер бөлек жұмысын жалғастырады, ал агрегацияланған интерфейс жұмыс істемейді.

Әрбір желілік интерфейсті, оның ішінде агрегацияланғанын, бір немесе бірнеше VLAN-ға қосуға болады.

## {heading(VLAN)[id=bare-metal-network-vlan]}

_VLAN_ (Virtual Local Area Network, [IEEE 802.1Q](https://www.ieee802.org/1/pages/802.1Q-2014.html) стандарты) — желілік инфрақұрылымның әртүрлі физикалық сегменттеріне, мысалы, әртүрлі коммутаторларға қосылғандай тәуелсіз және оқшауланған L2 желілерін құруға мүмкіндік беретін технология. Бір VLAN шеңберіндегі құрылғылар басқа VLAN трафигін, оның ішінде кең таралымды сұрауларды да көрмейді. Осылайша, трафик әртүрлі VLAN бойынша сегменттеледі, бұл әртүрлі мақсаттағы желілермен бөлек жұмыс істеуге мүмкіндік береді. Мысалы, клиенттік (production) және сынақ (development, stage) инфрақұрылымын бөлуге немесе әртүрлі жобалардың хосттар топтарын оқшаулауға болады.

Әрбір VLAN-ның `2`-ден `3999`-ға дейінгі VLAN ID мәні бар, ол {var(cloud)} жобасы шеңберінде бірегей.

VLAN трафигі желілік интерфейс арқылы екі тәсілдің бірімен беріледі:

- Тегпен (tagged): Ethernet-кадрға VLAN ID бар тег қосылады, құрылғылар кадрдың қай VLAN-ға жататынын сол арқылы анықтайды.
- Тегсіз (untagged): Ethernet-кадр VLAN ID қамтымайды, ал қабылдаушы жақ оны Native VLAN-ға жатқызады.

    _Native VLAN_ — трафигі интерфейс арқылы тегсіз берілетін VLAN. Ол {linkto(../../instructions/manage-net#bare-metal-network-config-nic-or-bond)[text=желіні баптау]}, жаңа серверге {linkto(../../instructions/manage-service#bare-metal-manage-service-order)[text=тапсырыс беру]} немесе ОЖ {linkto(../../instructions/os-setup#bare-metal-os-setup)[text=орнату]} кезінде беріледі. Native VLAN міндетті түрде тағайындалады және әрбір желілік интерфейсте тек біреу ғана болады.
