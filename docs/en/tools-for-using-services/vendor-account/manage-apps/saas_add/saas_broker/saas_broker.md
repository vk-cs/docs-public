# {heading(Broker for a SaaS application)[id=saas_broker]}

{include(/en/_includes/_translated_by_ai_en.md)}

The Store interacts with the service via a broker.

Develop a broker for a SaaS application using the VK OSB protocol. To obtain the VK OSB protocol, send an email to [marketplace@cloud.vk.com](mailto:marketplace@cloud.vk.com). The broker must implement methods describing the lifecycle of service instances ({linkto(#pic_saas_broker)[text=figure %number]}).

{caption(Figure {counter(pic)[id=numb_pic_saas_broker]} — Interaction of the broker with the Store and the SaaS application)[align=center;position=under;id=pic_saas_broker;number={const(numb_pic_saas_broker)} ]}
![pic1](../../assets/SaaS_broker.png){params[noBorder=true]}
{/caption}

The broker must have basic authentication configured over the secure HTTPS protocol with a certificate issued by a trusted certificate authority.

{note:err}

The use of self-signed certificates is prohibited.

{/note}

The broker can be developed based on a template that already implements the interaction between the Store and the broker. The template must be supplemented with a description of the broker's interaction with a specific SaaS application.

To develop a broker based on the template:

1. Send an email to [marketplace@cloud.vk.com](mailto:marketplace@cloud.vk.com) to obtain the broker template. The template is written in Python based on the [FastAPI](https://fastapi.tiangolo.com/tutorial/first-steps/) framework.
1. Develop a client for interacting with the service API.
1. Develop a service manager describing the interaction between the broker and the service:

   1. Implement a method for creating a tenant/account that takes as input:

      * The OSB ID of the service instance, which is generated by the Store when the service is connected. The OSB ID is passed to the SaaS application so that the SaaS application generates the service instance ID. The service instance ID is used in the methods described below.
      * The tariff plan ID.
      * The tariff options of the plan, described in the `plans.schemas.service_instance.create` section of the JSON file.
      * The context (optional). The context contains information about the user (email, OpenStack PID).

   1. Implement a method for updating a tenant/account that takes as input:

      * The service instance ID.
      * The tariff plan ID.
      * The tariff options of the plan, described in the `plans.schemas.service_instance.update` section of the JSON file.

   1. Implement methods for retrieving and deleting a tenant/account that take as input the service instance ID.
   1. Implement a method for creating service bindings that takes as input:

      * The service instance ID.
      * The service binding parameters, described in the `plans.schemas.service_binding.create` section of the JSON file.
      * The context (optional). The context contains information about the user (email, OpenStack PID).

   1. Implement methods for retrieving and deleting service bindings that take as input:

      * The service instance ID.
      * The service binding ID.

1. Integrate the client into the service manager.
1. Configure authentication in the broker.

If the SaaS application has postpaid tariff options and metrics for them are collected using the pull model (for more details, see the section {linkto(../../concepts/about#xaas_billing)[text=%text]}), perform the following additional steps:

1. In the service manager, implement a method for obtaining a report on the actual resources used by the SaaS application. In response to the request, the broker must send the report to the Store.
