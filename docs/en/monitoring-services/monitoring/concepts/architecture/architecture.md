# {heading(About the service)[id=monitoring-architecture]}

{include(/en/_includes/_translated_by_ai.md)}

The Cloud Monitoring service consists of several parts:

- A scalable API for ingesting metrics
- Distributed metric storage
- A scalable API for reading metric values and building queries
- Agents for sending standard metrics
- A UI for building dashboards and graphs
- A service for centralized updates of monitoring agents

## {heading(Namespaces)[id=monitoring-namespace]}

Each service writes data to its own namespace. The standard namespace names generated by {var(cloud)} services have the format `mcs/servicename`. If you need to write custom metrics, the namespace name should not start with `mcs/`.

## {heading(Labels)[id=monitoring-label]}

Labels carry additional metainformation that can identify the target resource being monitored. For example, in the case of a VM, this is the VM name or VM ID.

For each metric sent to storage, you can specify an arbitrary set of "key-value" pairs (labels).  For example, if you want to send the hostname of the virtual machine and the name of the availability zone it is located in along with the value of the cpu_total metric, you need to fill in the values for the 'host' and 'availability_zone' labels.

The submitted labels and their values are saved to the Cloud Monitoring database. Values of the same metric are automatically aggregated with a precision of 1-minute, 5-minute, and 1-hour periods. Aggregation is performed across all label fields with which the metric value was saved.

The keys and values of labels can then be used to build queries that filter and group metric values. For example, you can build a query in a format similar to PromQL:

```promql
SUM BY(host) (cpu:Minimum{instance="<"span >"server1", app!="<"span >"system"})
```

```promql
SUM BY(job) (cpu:Average{host="<"span >"server1", job!="<"span >"system"}[12h] offset 24h)
```

## {heading(PromQL query language)[id=monitoring-mon-read-metrics]}

To retrieve metric values, Cloud Monitoring provides an API with support for a subset of the PromQL query language.

Query syntax, filtering operators, and aggregation functions are described in the [official Prometheus documentation](https://prometheus.io/docs/prometheus/latest/querying/basics/).

## {heading(Aggregation)[id=monitoring-aggregation]}

Key characteristics of the aggregation process:

- Cloud Monitoring automatically aggregates metric values over 1-minute, 5-minute, and 1-hour intervals
- Raw metric values are automatically deleted after aggregation
- The following aggregation functions are supported out of the box:

  - Minimum
  - Maximum
  - Average

- Aggregation is performed across all label fields with which the metric value was saved
- Aggregated metrics are stored for 30 days
- Users can retrieve aggregated metric values filtered by the required label values

## {heading(Units of measurement)[id=monitoring-units-of-measurement]}

Cloud Monitoring has standard units of measurement that can be sent and aggregated by:

- `Seconds`,
- `Microseconds`,
- `Milliseconds`,
- `Bytes`,
- `Kilobytes`,
- `Megabytes`,
- `Gigabytes`,
- `Terabytes`,
- `Bits`,
- `Kilobits`,
- `Megabits`,
- `Gigabits`,
- `Terabits`,
- `Percent`,
- `Count`,
- `Bytes/Second`,
- `Kilobytes/Second`,
- `Megabytes/Second`,
- `Gigabytes/Second`,
- `Terabytes/Second`,
- `Bits/Second`,
- `Kilobits/Second`,
- `Megabits/Second`,
- `Gigabits/Second`,
- `Terabits/Second`,
- `Count/Second`,
- `None`.

If no unit of measurement is specified, `None` is assumed.
